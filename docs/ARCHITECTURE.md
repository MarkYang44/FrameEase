# FrameEase 架构

## 总览

```
┌──────────── 窗口（React + TS，系统 WebView）────────────┐
│ 转码 / 截取 / 封装 / 信息 / 设置                          │
│ zustand 状态：设置草稿、待处理文件、队列（由事件驱动）     │
└───────────────▲──────────────────────┬───────────────────┘
        事件 fe://job, fe://queue …   │ 命令 invoke(...)
┌───────────────┴──────────────────────▼───────────────────┐
│ src-tauri：命令桥接、启动检测（能力缓存）、退出保护、       │
│            调试版开发桥接（feature dev-bridge）             │
└───────────────▲──────────────────────┬───────────────────┘
                │ EventSink            │ Engine API
┌───────────────┴──────────────────────▼───────────────────┐
│ crates/fe-core（不依赖 Tauri，可单独测试）                 │
│  scan → media(probe) → plan → process(ffmpeg) → verify →  │
│  fsx.commit；engine 调度/持久化；manifest 结果记录         │
└──────────────────────────────┬────────────────────────────┘
                               │ 参数数组（无 shell）
                        ffmpeg / ffprobe（随包附带）
```

## 模块职责（fe-core）

| 模块 | 职责 | 关键约束 |
|---|---|---|
| `tools` | 定位后端：用户指定 → 随包附带 → 便携目录 → 系统（含 Homebrew 目录，因为 macOS 图形应用不继承 shell PATH） | 用户无需配置 PATH |
| `caps` | 版本/许可、编码器与像素格式、滤镜、复用器；硬件编码器用真实参数做一次测试编码（质量模式失败再试码率模式、10-bit 单独测）；硬件解码实测；无损自检 | 只信实测结果；结果按 FFmpeg 路径+大小+修改时间缓存 |
| `media` | ffprobe JSON → `MediaInfo`；像素格式特征表；显示矩阵 → 顺时针旋转；HDR（PQ/HLG）、母版显示/内容亮度（必要时读首帧 side data）；VFR 按前 600 个包时间戳判断 | 所有路径以 `file:` 协议传给 FFmpeg，避免被当成 `concat:`/`http:` 等协议 |
| `encoders` | 每个编码器的质量刻度（方向、范围、0/100 档对应值）、速度预设、码率、两遍、无损方式、线程参数（x264 `-threads`、x265 `pools`、SVT-AV1 `lp` 并行级别） | 不同编码器的 CRF/CQ 不互相比较或复制 |
| `plan` | 设置快照 + 媒体 + 能力 → 参数数组 + 校验期望 + 警告/阻断问题 | 纯函数；见下方规则 |
| `process` | 启动子进程（stdin 关闭、Windows 无控制台、Job Object）、解析 `-progress`、按字节读取 stderr 写日志并保留尾部、取消即结束进程；退出通知之外每 500 ms 轮询一次退出状态；停滞检测（帧数/时间/体积计数长时间不变即结束进程） | 从不经过 shell；任何情况下都不会无限等待 |
| `verify` | 按实际探测结果校验 | 见下方“校验” |
| `fsx` | 文件名清理与模板、同路径检测、临时文件命名、原子不覆盖提交、可用空间 | 只删除匹配临时文件模式的文件 |
| `engine` | 队列、调度、状态机驱动、事件、持久化、恢复、结果记录 | 单个任务的任何失败都不影响队列 |
| `store` | JSON 原子写入（临时文件 + fsync + rename，保留 `.bak`），读取失败回退备份，损坏文件移到旁边而不删除 | |
| `manifest` | 结果 CSV（UTF-8 BOM，Excel 可直接打开） | 打开/写入失败只暂存，稍后补写 |
| `scan`/`trial`/`presets` | 导入扫描、试压与取帧、预设导入导出 | |

## 任务状态机

```
Waiting ──► Probing ──► Encoding ──► Muxing ──► Verifying ──► Done（终态，不重跑）
   │           │  └──────────────► Muxing（流复制任务）  │
   │           └──► NeedsInput ◄── Waiting                │
   ▼           ▼            ▼            ▼               ▼
Cancelled   Failed / Cancelled / Waiting（应用退出时被中断，下次从头开始）
Failed、Cancelled ──重试──► Waiting；NeedsInput ──用户选择修正──► Waiting
```

转换表在 `job.rs` 的 `can_transition_to`，非法转换被拒绝（有单元测试）。`Done` 之后“重新处理”会新建任务，而不是复用。

## 参数规划规则（plan.rs）

- 输出编码就是用户选的编码：GPU 速度档没有可用硬件编码器时给出问题（可改用 CPU），**不会**自动换编码器或换编码格式。
- 默认不缩放、不改帧率；帧时间戳透传（`fps_mode passthrough`，保留可变帧率）。缩放/裁切/旋转/改帧率只在用户明确选择时出现，并计算出精确的期望分辨率。
- 带旋转矩阵的源：重编码时按显示方向输出（像素转置，不损失画质），流复制时保留矩阵。
- 像素格式：优先保持源格式；编码器不支持时选同色度、同位深的等价格式（如 nv12→yuv420p）；需要降低位深或色度采样时必须由用户明确允许；HDR 源只允许已验证保留 HDR10 元数据的 x265/SVT-AV1，否则拒绝（未实现色调映射）。
- 无损：编码器 + 实际输入像素格式必须通过自检，否则要求先自检或给出可用替代（x264/x265/FFV1…）；不允许任何画面变换或烧录字幕；不强制 `-pix_fmt`；软件解码。
- 音频：可复制则复制并在校验时比对数据哈希；不兼容时按策略（默认先问用户）。MP4 的可复制白名单按主流播放器兼容性而不是“复用器是否接受”（FFmpeg 8 能把 PCM 写进 MP4，但多数播放器无法播放）。
- 字幕：MKV 原样复制；MP4 中文字字幕转 mov_text（ASS 样式丢失会提示），图形字幕需改用 MKV 或不保留；烧录文字字幕需要 libass，字幕先复制/提取到任务工作目录的 ASCII 文件名，避免滤镜路径转义问题。
- 截取：流复制从不晚于所选起点的关键帧开始（会提示实际起点，期望时长也按实际起点计算）；重编码时输入端精确定位。
- 输出永远写入 `-n`（不覆盖）的临时文件；HEVC 放入 MP4 时加 `hvc1` 标签。

## 校验（verify.rs）

1. 文件非空且能被 ffprobe 识别；容器类型正确。
2. 视频：实际编码（不看扩展名）、宽高、像素格式、旋转、色域/传递/矩阵/范围标记、HDR 母版元数据（源有则必须保留）。
3. 帧数：与源包数一致（允许 0.1%）；改帧率或截取时按期望帧数 ±2%。
4. 时长（容差 max(0.6 秒, 1%)）、音轨与字幕数量、各音轨编码。
5. 复制的轨道：包级 SHA-256 一致；重新封装导致包格式变化（如 ADTS→MP4）时退而比对解码后数据。
6. 无损：源（相同截取参数）与输出逐帧 framemd5 完全一致。
7. 其余情况完整解码一遍（`-xerror`，任何解码错误即失败）。

任一项失败：任务标记失败并保留报告，临时文件删除，原有文件不受影响。

## 文件安全（fsx.rs + engine.rs）

- 输出先写到 `<最终名>.fe-<任务编号前 8 位>.part`（与最终文件同目录，保证可原子重命名）。启动编码进程**之前**就把临时路径写进持久化队列，崩溃后也能找到并清理。
- 提交：macOS `renamex_np(RENAME_EXCL)`、Linux `renameat2(RENAME_NOREPLACE)`、Windows `MoveFileExW`（不带替换标志）；文件系统不支持时退回 `link()`，再不行才“检查后重命名”。目标已存在时按“自动编号”找下一个名字，或按“跳过”结束任务。
- 删除：只删除匹配 `.fe-xxxxxxxx.part` 模式且属于该任务记录的文件；源文件永不删除（有测试）。
- 磁盘：开始前检查可用空间（预估上限 + 512 MB 余量）；编码中每 3 秒检查，低于 256 MB 时停止该任务并给出原因。

## 持久化与恢复（engine.rs + store.rs）

- 每次状态变化后（防抖 300 ms）原子写入 `queue.json`；关键节点（启动后端前、记录 PID 后、任务结束时）立即写入。
- 启动时：结束上次残留的 ffmpeg 进程（按记录的 PID，且进程名确为 ffmpeg 才结束，避免 PID 复用误伤）；删除本应用的临时文件；运行中的任务回到“等待”并标记“上次中断，将从头开始”；队列默认暂停，由用户点“继续处理”。
- 已完成且已校验的任务保持完成，不会重跑。

## 卡死恢复

SVT-AV1 4.1 在多路高并发时偶发内部死锁（采样：所有流水线线程阻塞在 `svt_block_on_semaphore`，FFmpeg 仍按时输出进度但计数不再增加）。处理方式：

1. SVT-AV1 的并行级别 `lp` 总是按任务线程预算显式设置，不交给编码库自动决定（实测可降低触发概率）。
2. `StallTracker` 以“计数不再变化”而不是“没有输出”判断卡死；收尾阶段（`progress=end` 之后移动 moov）不计入。默认 5 分钟，libaom 15 分钟（`engine::stall_limit_for`，可由 `EngineConfig::stall_limit` 覆盖）。
3. 卡死时结束进程、删除该次的临时输出、以完全相同的参数重试该步骤一次，并在任务上留下提示；再次卡死才判定失败（`backendHung`），队列继续处理其他任务。

## 调度与资源

- 并行“自动”：CPU 编码 1 路（16 线程以上且 16 GB 以上内存时 2 路），每路线程数 = 逻辑核心数 / CPU 路数；另有 1 路给 GPU 编码和流复制这类不占满 CPU 的任务。用户也可以固定 1–4 路。
- 开始任务前检查可用内存是否满足该任务的估计峰值（按编码器与分辨率估算，另留 1 GB）；不满足时按队列顺序等待，界面显示原因。
- 有损任务在硬件解码经过实测时使用它，把解码交给媒体引擎，让 CPU 专心编码。

## 界面与后端通信

- 命令：`bootstrap`、`probe_files`、`scan_inputs`、`plan_preview`、`describe_settings`、`enqueue`、`queue_*`、`trial_run`、`extract_frame`、`keyframes`、预设与配置等（`src-tauri/src/commands.rs`）。
- 事件：`fe://job`（单个任务，进度事件每任务最多每 250 ms 一次，状态变化立即发送）、`fe://queue`、`fe://manifest`、`fe://caps`、`fe://init`、`fe://close-requested`。
- 打开/在文件夹中显示只接受队列中已知的路径（输入、输出、日志）、数据目录和结果记录。
- 关闭窗口或退出时若有任务进行中，阻止退出并在界面中询问；确认后停止任务、清理临时文件、保存队列再退出。

## 开发桥接（仅调试构建）

`--features dev-bridge` 时，调试版在 `127.0.0.1:1430` 提供 `/invoke/<命令>`、`/events?since=`、`/file?path=`（只限预览目录）。前端在普通浏览器中以 `?bridge` 打开时改用这条通道。它用于在没有屏幕录制权限的环境下，用真实后端驱动界面做自动化检查；发布构建不含此代码（`cfg(all(feature = "dev-bridge", debug_assertions))`）。
