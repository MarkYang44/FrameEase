FrameEase 0.1.3 fixes three cases where a correct conversion was reported as failed, and catches incomplete source files before any encoding starts.

## Fixes

- **Full-range video no longer fails verification.** Many phone apps record full ("JPEG") range. FrameEase keeps that range as intended, but the pixel-format check compared names, and FFmpeg calls full-range 8-bit H.264/HEVC `yuvj420p`, so a faithful output was reported as "pixel format: expected yuv420p". Names are now compared with that spelling folded in; the color range keeps its own check.
- **Frames hidden by an edit list no longer count as lost.** MOV/MP4 files trimmed without re-encoding can carry leading frames that an edit list hides; players and FFmpeg skip them. The frame-count check counted them anyway (for example, 1081 expected and 1066 found). Only frames that are actually shown are counted now.
- **Incomplete downloads are caught when you add them.** An MP4/MOV whose index survived but whose data stops early used to be encoded and then fail on "duration". FrameEase now checks that the data reaches the end the file declares, and stops before encoding with "The source is incomplete", showing how much can be read. **Process the readable part only** converts just that part and notes it on the job.

Jobs that failed for these reasons can simply be retried after updating.

## Validation

New regression tests use generated clips with each property: full range encoded with x264, x265 and VideoToolbox; an edit list hiding 15 frames; a file cut off at 55%. The six real files that showed the problem were re-run with this build: all complete and verify, and the incomplete one is processed up to where its data ends. The release includes the macOS Apple Silicon DMG, the Windows EXE/MSI installers, the Windows no-install ZIP, and `SHA256SUMS.txt`.

## 简体中文

本版修复三种“输出其实正确，却被判为校验失败”的情况，并在开始处理前识别不完整的源文件。

- **全范围视频不再误报“像素格式”**：许多手机 App 录制全范围（JPEG range）视频，FrameEase 本就保留原范围，但旧的校验按名称比较，把 FFmpeg 对全范围 H.264/HEVC 的叫法 `yuvj420p` 当成了不一致。现在比较时忽略这种写法差异，色彩范围仍单独校验。
- **编辑列表隐藏的开头帧不再算作丢帧**：未重新编码就剪辑过的 MOV/MP4 可能带有被编辑列表隐藏的开头帧，播放器和 FFmpeg 都会跳过，旧的帧数校验却把它们算了进去（例如预期 1081、实际 1066）。现在只统计实际显示的帧。
- **添加文件时识别未下载完整的视频**：文件头完整、数据却中途截断的 MP4/MOV 过去会先编码，最后以“时长”校验失败告终。现在添加时就提示“源文件不完整”并说明能读到哪里；选择“只处理可读的部分”即可只转换这一段，任务上会注明。

因上述原因失败的任务，更新后直接点“重试”即可。
